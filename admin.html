Note — How SiteScout works

Reference for the SiteScout look-up tool. Open it from the SiteScout tab in the sidebar.

  1. Enter a website once, then choose a tool: Check SEO on every page, See what's on Google or Map the site. Pressing Enter runs the SEO check. Quick picks (★ My site and recent sites) fill in the box. Your own Edgeducate domains switch to owner mode (all your domains + live Search Console); any other domain is analysed as a single external site.
  2. Sitemap scan. SiteScout reads the site's public /sitemap.xml to discover its live pages, then draws them as an interactive map around the homepage.
  3. Explore the map. Open it full screen; drag nodes, drag empty space to pan, and scroll to zoom. Click a link line to highlight that connection and open the connected page.
  4. On-page SEO audit. Click any page to fetch it live and grade real signals: title, meta description, H1, canonical, structured data, word count, and image alt text.
  5. Website inspect. Enter a domain to inspect every page in its sitemap (up to 150) in one pass. The site overview groups problems — missing titles, meta descriptions or canonicals, heading errors, missing structured data, breadcrumbs, Open Graph or alt text — by how many pages they affect. Click any page to open its full page inspect report inside the same view. Page inspect is still available on its own for single pages.
  6. Outbound references. Each audit lists external links, linked domains, and sponsored / nofollow tags — useful for spotting guest posts, partners, and paid links.
  7. Private scouting. When set up, requests to other companies route through your Cloudflare proxy Worker, so they see the proxy — not your IP. Once configured it stays on for every search.
  8. Live Search Console (your site only). Connect the GSC Worker to see real clicks, impressions, average position, and top queries per page. The dialog shows your remaining free Worker calls for the day.
  9. Sitelinks schema (your site only). Generates ready-to-paste JSON-LD (WebSite + SearchAction, Organization, BreadcrumbList) to help Google show a sitelinks search box and breadcrumbs.

Everything runs on free tiers. True inbound backlinks (who links to a site) need a paid index like Ahrefs/Moz; SiteScout detects the page-readable, outbound half for free.

                      Migrate To A New Computer

                      Use this checklist when moving permanently to a new machine. It covers full source + resources migration.

                      Current project root: unavailable Current admin-desktop folder: unavailable
                      1. On this computer, push final changes first.
                        Click Deploy and confirm no push errors in Activity log.
                      2. Copy the full project source to the new computer.
                        Copy the entire project folder (the folder containing admin-desktop, data, cloudflare, resource-pages, and all root files like admin.html, admin.js, resources.html).
                      3. Minimum required folders/files if you cannot copy everything.
                        Copy admin-desktop/, data/, resource-pages/, assets/, plus root files used by the admin/site (admin.html, admin.js, all-resources.html, resources.html, script.js, styles.css, wrangler.toml).
                      4. Set environment values on the new computer.
                        Create admin-desktop/.env from .env.example and fill SMTP + ADMIN_EMAIL_TO values.
                      5. Install prerequisites and run.
                        Install Git and Node.js, run npm install in admin-desktop, then run start-app.bat.
                      6. Optional: migrate local login state (trusted transfer only).
                        Copy auth.json from this machine to the same userData location on the new machine.Current auth.json path: unavailable
                      7. Final verification on the new computer.
                        Open admin, click Pull data, make a small edit, click Deploy. If both pull and push succeed, migration is complete.

                      Tip: keep this computer unchanged until the new computer passes one full pull/edit/deploy cycle.
